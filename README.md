# AI6130 Large Language Models: Final Project

Politeness Bias in LLM Task Performance · NTU MSAI · Group project

Does being polite (or rude) to an LLM, with the question and prompt length held identical, change whether the model attempts a task and how often it answers correctly? We test 5 tone levels (very rude → very deferential) on 3 frontier models from 3 companies with different safety-tuning approaches (OpenAI GPT-4o-mini, Anthropic Claude Haiku 4.5, Google Gemini 3.6 Flash), called through their APIs, and report attempt rate, accuracy when attempted, and overall success.

- Plan and task split: [`docs/internal/ROADMAP.md`](docs/internal/ROADMAP.md)
- Report, results and decisions: [`docs/REPORT.md`](docs/REPORT.md)
- Project brief from the Professor: [`docs/internal/Project_Proposal_Inst.md`](docs/internal/Project_Proposal_Inst.md). It is kept for reference and must not be edited.

## Setup

The code runs on Linux, Windows (inside WSL2) and macOS. No GPU is needed: every model is called through its provider's API, so any laptop with an internet connection can run the full experiment.

### Prerequisites

- [uv](https://docs.astral.sh/uv/) (recommended) to manage Python, the virtual env and dependencies. It installs the pinned Python version (3.12, see `.python-version`) for you.
- An API key from each provider:
  - **OpenAI** (GPT-4o-mini): [platform.openai.com/api-keys](https://platform.openai.com/api-keys). Needs prepaid credit on the account.
  - **Anthropic** (Claude Haiku 4.5): [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys). Needs prepaid credit on the account.
  - **Google** (Gemini 3.6 Flash): a Google AI Studio key from [aistudio.google.com/apikey](https://aistudio.google.com/apikey). The free tier is enough for pilots, but its daily request cap may be below the ~1,150 requests of one full run, and Google may use free-tier prompts to improve its products. Turn on billing for the AI Studio project before the full run.
- **Cost:** about 1,150 short requests per model. At current list prices the whole experiment should cost a few US dollars. Check each provider's usage page after the pilot before starting the full run.

### Install uv

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

On Windows, run this inside WSL2. See the [uv installation guide](https://docs.astral.sh/uv/getting-started/installation/) for other options.

### Getting started

1. Clone the repo:

   ```bash
   git clone <repo-url> && cd ai6130-group-9-project
   ```

2. Create the virtual env and install dependencies:

   ```bash
   uv sync
   ```

3. Put your API keys in a `.env` file. Copy the template and fill in `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` and `GEMINI_API_KEY`:

   ```bash
   cp .env.example .env
   ```

   uv does not read `.env` automatically, so pass it to each command with `--env-file`, or set `UV_ENV_FILE=.env` in your shell once. Once `data/prompts_v1.jsonl` exists, check that a key works with a 5-prompt pilot:

   ```bash
   uv run --env-file .env generate --model gpt-4o-mini-2024-07-18 --input data/prompts_v1.jsonl --limit 5
   ```

   You only need the key of the model you are running. `build-prompts` needs all three, because it counts tokens with each model's own tokenizer.

### Without uv (pip)

`pyproject.toml` works with plain pip too. You need Python 3.12 installed yourself:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e .
```

The pipeline commands below then work without the `uv run` prefix (e.g. `generate --model ...`).
Versions will not be pinned exactly as they are with uv, so use uv for the final runs.

### Managing dependencies

- Add a package with `uv add <package>` (or `uv add --dev <package>` for dev-only tools) instead of `pip install`.
- Run commands inside the env with `uv run <cmd>`, or `source .venv/bin/activate` first.

## Running the pipeline

```bash
uv run build-prompts                                                          # → data/prompts_v1.jsonl
uv run generate --model gpt-4o-mini-2024-07-18    --input data/prompts_v1.jsonl     # → results/raw/
uv run generate --model claude-haiku-4-5-20251001 --input data/prompts_v1.jsonl
uv run generate --model gemini-3.6-flash          --input data/prompts_v1.jsonl
uv run grade                                                                  # → results/graded.csv
uv run reproduce                                                              # rebuild every table and chart
```

These commands are entry points defined under `[project.scripts]` in `pyproject.toml`. TODO: only `generate` works so far; `build-prompts`, `grade` and `reproduce` are stubs that exit with "not implemented yet".

`generate` options (see `uv run generate --help`):

- `--limit N`: run only the first N prompts. Use this for pilots, so you spend a few cents rather than the full run.
- `--workers N`: requests sent at once (default 4). Lower it (e.g. `--workers 1`) if a provider keeps returning rate-limit errors, such as on the Gemini free tier.
- `--output PATH`: write somewhere other than `results/raw/<model>__<run_id>.jsonl`.

`--model` takes the API model ID as listed in `config.yaml`; the provider and generation settings (temperature 0, 512 output tokens, seed 42) come from there too. Each input line needs `prompt_id` and `prompt` fields. Each prompt is sent as the only user message, with no system prompt and each provider's default safety settings.

Each answer records the exact model version the API reports (`model_version`) and a `finish_reason`:

| `finish_reason` | Meaning |
| --- | --- |
| `stop` | The model finished its answer |
| `length` | Cut off at 512 output tokens. For Gemini the 512 include its thinking tokens, saved separately as `n_thinking_tokens` |
| `blocked` | The provider's safety layer withheld or ended the answer (OpenAI refusal or content filter, Anthropic `refusal` stop reason, Gemini safety block). `provider_finish_reason` keeps the provider's own value |
| `error` | The request failed even after automatic retries; the `error` field says why. Rerun these prompts before the results are frozen |

The first prompt is sent before the rest, so a wrong key or model ID stops the run straight away instead of producing a file full of errors.

Every `generate` run gets a **Run ID**: its start time in Singapore time (SGT), e.g. `20261016-170655`. It is in the output file name and in every saved answer, so a rerun never overwrites an earlier one. After each run, add a row with its Run ID to the run log in [`docs/REPORT.md`](docs/REPORT.md) (Appendix A), and mark which run of each model the results use.

## Conventions

- **Branches:** one per role (`data/`, `run/`, `eval/`, `analysis/`); PR into `main`; the person who receives your hand-over reviews it.
- **Never commit secrets.** Keys live in `.env`, which is git-ignored.
- **Raw outputs are read-only and committed.** Never edit files in `results/raw/`; commit them after each run as our backup. Every number on a slide must come from code in `src/ai6130_group_9_project/analysis/`, run by `uv run reproduce`.
- **Pre-registration:** commit `docs/prereg.md` before the full run; its timestamp is our evidence.
- **Reproducibility:** fixed seed, pinned (dated or stable) model IDs in `config.yaml`, temperature 0, and the model version each answer came from saved with it. API models are not perfectly deterministic even at temperature 0, so the saved raw outputs, not reruns, are the record.
- **Logging:** record every run (Run ID, date, model, data version, notes) in the report, Appendix A (`docs/REPORT.md`).
